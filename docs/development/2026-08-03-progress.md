## 關鍵決策與討論(為什麼)

- **WebP 的定位**(v0.2.0):實測發現同預算下 WebP 幀數並沒有比 GIF 多
  (品質較高、每幀較大),真正價值是「APNG 塞不進、GIF 得犧牲色彩時,
  只有 WebP 能以真彩 + 8-bit alpha 填滿 Discord 預算」。文件已照實寫。
- **策略軸與 `--priority` 正交**(v0.4.0):`--priority` 管「幀數 vs 畫面
  大小」;`--strategy` 管「幀數 vs 色彩」,兩軸可組合。
- **balanced 的實驗定案**(v0.5.0,`docs/experiments/2026-07-23-strategy-matrix.md`):
  20 格 fps×色數矩陣、每格都塞進預算、使用者肉眼排名。結論**不對稱**:
  貼圖 320px 大圖近看 → 96 色保色彩(148 幀);表情實際顯示 32px → 色彩
  不可見 → 32 色全換流暢(98 幀)。star_spin 對照組證明色彩軸對平塗圖是
  無害 no-op(c256 實際只用了 128 色,全是 AA 邊緣過渡)。
- **發版全自動**:push `v*` tag → GitHub Actions 自動建 Release(notes =
  tag 註解 + changelog)。途中修過一個坑:actions/checkout 會把 tag 物化成
  lightweight 蓋掉註解,workflow 內需 force re-fetch 真 tag。本地備援:
  `scripts/release.sh`(compose `release` profile)。
- **repo 衛生**(2026-07-22):`docs/references/external_{repos,sites}/` 與
  `docs/local/` 改為 local-only(只追 `.gitkeep`),歷史用 filter-branch
  清除並 force-push;檔案本體都留在本機原位。
- **gifsicle 釘 1.95**:1.96 的 `--lossy` 對平塗動畫幀失效(省 0.06% vs
  43%),升級前先跑 hajime 回歸。
